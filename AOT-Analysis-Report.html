1. 严重问题 — DataTable XML 序列化 (IL3050)

IL3050 DataTable.ReadXml / WriteXml 需要 DynamicCode
DataTable.ReadXml() 和 DataTable.WriteXml(XmlWriteMode.WriteSchema) 内部使用 XmlSerializer， 后者依赖 System.Reflection.Emit 动态生成程序集。Native AOT 不支持运行时动态代码生成， 因此这些调用在 AOT 编译后运行时必然崩溃。
文件行号调用影响
Program.cs32WriteXml("AppSettings.xml", WriteSchema)初始化时崩溃
Program.cs36ReadXml("AppSettings.xml")启动时崩溃
frmMain.cs13ReadXml("DesktopList.xml")主窗体加载崩溃
frmMain.cs57WriteXml("DesktopList.xml", WriteSchema)删除桌面时崩溃
frmAddDesktop.cs29WriteXml("DesktopList.xml", WriteSchema)添加桌面时崩溃
frmSet.cs24WriteXml("AppSettings.xml", WriteSchema)保存设置时崩溃
frmClose.cs17WriteXml("AppSettings.xml", WriteSchema)退出时崩溃
frmClose.cs29WriteXml("AppSettings.xml", WriteSchema)退出时崩溃
修复方案：用 System.Text.Json 替换 DataTable XML 序列化
// 定义数据模型替代 DataTable public class AppSettingsData { public int Color { get; set; } public int ExitMode { get; set; } } public class DesktopEntry { public string? Name { get; set; } public string? Path { get; set; } } // 读写使用 System.Text.Json（AOT 兼容，支持 source generator） var settings = JsonSerializer.Deserialize<AppSettingsData>(File.ReadAllText("AppSettings.json")); File.WriteAllText("AppSettings.json", JsonSerializer.Serialize(settings)); // 桌面列表 var list = JsonSerializer.Deserialize<List<DesktopEntry>>(File.ReadAllText("DesktopList.json")); File.WriteAllText("DesktopList.json", JsonSerializer.Serialize(list));

应对策略

3. 警告 — _SuppressWinFormsTrimError 掩盖问题

配置风险 _SuppressWinFormsTrimError=true 隐藏修剪错误
MultiDesktop.AOT.csproj:13 中设置了 _SuppressWinFormsTrimError=true。 此内部标志将 WinForms 的修剪分析错误（本应导致构建失败）降级为警告，使构建能够通过。 但被抑制的错误可能在运行时表现为控件属性丢失、绑定失败或异常。
<!-- 当前配置 --> <_SuppressWinFormsTrimError>true</_SuppressWinFormsTrimError> <!-- 潜在风险点 --> // frmMain.Designer.cs:31 — ComponentResourceManager 使用反射设置控件属性 ComponentResourceManager resources = new ComponentResourceManager(typeof(frmMain)); resources.ApplyResources(tblDesktopList, "tblDesktopList"); // 位置/大小/文字等 resources.ApplyResources(btnAddDesktop, "btnAddDesktop");
建议
  • 暂时保留此标志以使构建通过，但需进行完整的运行时功能测试
  • 重点验证：所有窗体的控件位置/大小/文字是否正确显示（ApplyResources 是否生效）
  • 长期目标：移除此标志，逐个解决暴露的修剪警告
  • 确保所有窗体和控件类未被修剪器移除（检查 Designer 生成的 .resx 资源是否正确加载）

4. 次要 — Assembly.Location 返回空字符串 (IL3000)

IL3000 Assembly.Location 在单文件应用中返回空字符串
AOT 发布生成单文件应用，Assembly.Location 对内嵌程序集返回空字符串。 此警告来自 WinForms 框架内部（非项目代码），影响范围有限：
  • ThreadExceptionDialog.ThreadExceptionDialog(Exception) — 异常对话框中获取程序位置
  • Control.ControlVersionInfo.OwnerIsInMemoryAssembly — 控件版本信息
建议
  • 此为框架内部问题，项目代码无需修改
  • 如需获取应用目录，使用 AppContext.BaseDirectory 而非 Assembly.Location
  • 验证异常对话框（未处理异常时弹出）是否正常工作

6. 其他潜在问题（编译器未检测）

DataTable 数据绑定到 AntdUI.Table
frmMain.cs:21 — tblDesktopList.DataSource = DesktopManager.DesktopList 将 DataTable 直接绑定为数据源。数据绑定使用 TypeDescriptor 和 PropertyDescriptor（基于反射）， 在 AOT 修剪后可能无法正确发现 DataTable 的列属性。
建议
  • 如果替换 DataTable 为强类型模型（如 List<DesktopEntry>），数据绑定将更加 AOT 友好
  • 或者直接手动填充 AntdUI.Table 的数据，不使用 DataSource 绑定
frmAddDesktop.cs 残留 using MultiLangDll
frmAddDesktop.cs:2 — using MultiLangDll; 未被注释掉， 但 AOT 项目未引用 MultiLangDll.dll。C# 编译器允许不存在的 using（如果未使用其中类型）， 所以构建不会失败，但这是残留代码应清理。
Process.Start 打开 URL 需要显式设置 UseShellExecute
frmAbout.cs:23,32,44 — Process.Start("https://...") 在 .NET Core+ 中 UseShellExecute 默认为 false，直接传 URL 不会打开浏览器。 虽非 AOT 专有问题，但 AOT 应用中更常见此坑。
// 修复 ProcessStartInfo psi = new ProcessStartInfo { FileName = "https://github.com/Qibowen2008/MultiDesktop", UseShellExecute = true }; Process.Start(psi);

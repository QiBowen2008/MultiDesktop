## 桌面切换无感化改造：SHSetKnownFolderPath

### 背景
原方案 ChangeDesktopPath 通过改注册表 + kill explorer.exe + 重启 explorer 实现桌面切换，体验差（桌面闪烁1秒、文件管理器窗口全部关闭）。

### 修改文件
- `src/MultiDesktop/Program.cs`

### 具体改动
1. **新增 Win32 P/Invoke 声明**（DesktopManager 类内）：
   - `SHSetKnownFolderPath` (shell32.dll) — 官方 API，修改已知文件夹路径并通知 Shell 刷新
   - `SHChangeNotify` (shell32.dll) — Shell 变更通知（双重保险）
   - `FOLDERID_Desktop` GUID: `{B4BFCC3A-DB2C-424C-B029-7FE99A87C641}`

2. **重写 ChangeDesktopPath**：
   - 优先调用 SHSetKnownFolderPath（flags=0: 写注册表+立即刷新），成功后调 SHChangeNotify
   - 失败时回退到旧方案（改注册表 + kill explorer）
   - 新增 Directory.Exists 检查 + 自动创建目录

3. **更新 --help 文本**：将"桌面切换会重启 explorer.exe 进程，请保存好当前工作"改为"桌面切换即时生效，无需重启资源管理器"

## 修复桌面切换时壁纸判断逻辑

### 修改文件
- `src/MultiDesktop/frmMain.cs`

### 问题
`btnChangeDesktop_Click` 和 `itmDesktopList_DropDownItemClicked`（托盘菜单切换桌面）都只调用单参数 `ChangeDesktopPath(path)`，完全忽略了桌面的自定义壁纸配置。即使桌面设置了自定义壁纸，切换后也还是用当前壁纸。

### 修复
两处切换入口都添加了壁纸判断逻辑：
1. 从 DataTable 读取 `是否开启自定义壁纸`（列2，bool）和 `自定义壁纸地址`（列3，string）
2. 若开启且壁纸路径有效 → 调用 `ChangeDesktopPath(desktopPath, wallpaperPath)`（带壁纸重载）
3. 否则 → 调用 `ChangeDesktopPath(desktopPath)`（不修改壁纸）

Additionally fixed: `itmDesktopList_DropDownItemClicked` 补充了 `clickedItem is not null` 的空检查。

### 编译结果
0 错误，6 个 warning（全部为项目原有 nullable 警告）
